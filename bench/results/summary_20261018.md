# Test/improve loop results — 2026-10-18, pi 1.3.0, N=3/arm

Rounds: three improvement rounds on local Spark-X2.5-4B, a news-search round, a
scale-up round with OpenRouter's free Xing4.0 29B A4B (jev local), a multi-source
synthesis round, a router-preamble round, and a long-context extraction round.

## Long-context extraction round (>50k tokens) + KV q4_0

Fixtures (`bench/gen_bigfile.py`, deterministic): `bigfile.txt` 230 KB / ~58k tokens,
eight 64-hex salt needles + 48-hex decoy checksums; `bigfile_small.txt` ~9 KB sized to
the local 8k slot for a forced-paging variant (`bulk_far`: grep forbidden). Answer keys
live outside the agent-visible fixtures dir (one run found the key file and read it —
fixed).

- **bulk_extract (free strategy, 29B when the free endpoint was up): both arms 8/8** on
  the completed runs — and both arms *grepped* the 230 KB file instead of paging, so the
  salts were always fresh in context. Retrieval self-medication defeats the distance.
- **Engine KV cache moved to q4_0** (`-fa on -ctk q4_0 -ctv q4_0` in the jev launcher;
  note this llama.cpp build requires the `on` value): 7,021-token prompt
  prefills in 4.0 s (~1740 tok/s) on a consumer GPU, vs pre-change multi-minute
  context-spill-to-CPU runs.
- **bulk_far (forced paging, local 4B): mechanism verdict, not a scoreboard.** With
  thinking on, 5/6 runs die in thinking loops mid-paging; the one with-arm completion
  used `{var}` substitution and passed. With thinking off (`DH_SPARK_THINK=0`), all runs
  complete but **the baseline confabulated distant salts** — e.g. reported salt_3 as
  `bf877c98f90b3d40675ea0146d691c9b0a0b8982c3ad8255` (48 chars — the decoy checksum
  length) while asserting every value was 64-hex — and the with-arm failed only because
  thinking-off also collapses its placeholder compliance (the known round-1 trade-off):
  every completed with-run that used substitution was byte-exact; every retype drifted
  or fabricated.

Conclusion: when the source is far away or only partially attended, a 4B retyping is
unsafe and `{var}` substitution is byte-exact — the design target — but at 4B scale the
model's compliance with the quoting policy is itself unreliable (and thinking-on loops).
Fair long-context A/Bs need a main model that both complies and doesn't loop; the 29B
bucket (endpoint permitting) is the right place for `bulk_far`, `bulk_extract` numbers
above already show ceiling-level accuracy with free strategy.

## Router-preamble round: a system-prompt-alike injected into the jev state

The multi-source round's failures were NOT router-caused (transcripts showed correct
`chat` routing and model-side omissions), but the router's distributions were mushy on
ambiguous prompts (chat 40% / json 22% / code 18%). Fix: a concise routing preamble —
role, decision rule, per-format examples, precedence rules — sent as the leading
system message of the jev state (`bench/router_eval.py` keeps it in sync).

Measured on 18 labeled prompts (`python bench/router_eval.py`):

| config | correct | avg winner-prob |
|---|---|---|
| old (state = raw request) | 14/18 | 0.762 |
| **preamble injected** | **17/18** | **0.907** |

Old misroutes fixed live: `multi_conflict` `choice` 0.36 → `doc` 0.75 (no more spurious
closing round on non-choice prompts), `search_token`/`quote_hard` `code` → `chat`. The
one residual miss (`chat` vs `doc` on multi_conflict-style reads) is behaviorally
identical downstream. `run_hash`-style "run this exact command and report" still reads
as `code` (~0.62) — harmless: the checker validates the fenced output and the task
scores 3/3.

## Multi-source synthesis round: Xing4.0 29B, three sources-or-more per task

Tasks: combined summary of three funding rounds incl. the summed total · revised-vs-
preliminary conflict resolution (final doc supersedes) · three-region units/revenue
aggregation. Fixtures in `bench/fixtures/sources/` + the news corpus.

| task | with ext | without ext |
|---|---|---|
| multi_summary (3 sources + total) | 2/3 | 3/3 |
| multi_conflict (revision supersedes draft) | 3/3 | 3/3 |
| multi_regions (3-way aggregation) | 2/3 | 2/3 |
| **total** | **7/9** | **8/9** |

Verdict: at 29B, multi-source synthesis accuracy is dominated by the main model and the
extension neither helps nor hurts. Both arms resolve the superseding-revision conflict
perfectly; both arms length-flaked once on multi_regions (recovered by neither retry).
The unique failures: the with-arm once omitted the combined total while listing every
per-company figure correctly; the baseline once wandered off the archive to `curl` a
Google search and emitted a malformed tool call. (A scorer date-form strictness bug
— "Oct 3" vs "October 3" — was found during analysis and fixed; the numbers above are
post-fix re-scores of the same transcripts.)

## Scale-up round: Xing4.0 29B A4B main LLM, jev local (bench_20261018_112500)

| task | with ext | without ext |
|---|---|---|
| search_token / quote_config / quote_hard / run_hash / fix_bug | 3/3 each | 3/3 each |
| json_from_csv | 2/3* | 3/3 |
| news_funding / news_outage / news_latest | 3/3 each | 3/3 each |
| **total** | **26/27*** | **27/27** |

\* the single failure is an upstream **429 rate limit** on the free shared pool
(transcript shows three consecutive 429s), not extension behavior — functionally 26/26
among non-rate-limited runs. The bench now retries 429s like length flakes.

**Does jev still perform well at 29B scale? Yes — as designed.** The local 4B decision
service kept routing accurately against the much stronger main model (binary 99.6%,
json 91.7%, choice 91.7% in these logs) and its closing verdicts stayed correct (prime →
YES p≈1.0; news_latest → Tesserion-Halcyon 90.9%). Raw everyday-task accuracy hits the
ceiling on both arms at this scale (as expected — a 29B retypes short verbatim facts
correctly), so the extension neither helps nor hurts accuracy; what it adds is the
insurance/audit layer: closing verdicts with calibrated probabilities, format checking,
verification guard, `{var}` provenance, and empty-reply recovery.

## News search round (added after the loop below)

New capability: a `news_search` tool in the extension (local corpus by default —
`bench/fixtures/news/`, 8 hand-written confusable-but-realistic articles (Nordvine $48M /
Nordvane $84M / Nordline $48.5M; Kestrel DB 3.2 vs Cloud 2.8; Pulsegrid 4h12m/3.7M vs
Vantico 47min/210K) so priors cannot leak — plus a live mode via the HN Algolia API,
`DH_NEWS_LIVE=1`). Results register as `{news…}` template variables for exact quoting.

| task | with ext | without ext | note |
|---|---|---|---|
| news_funding (exact amount+date+headline among decoys) | 3/3 | 3/3 | both arms explicitly disambiguated decoys |
| news_outage (exact duration+impact vs decoy outage) | 3/3 | 3/3 | " |
| news_latest (which event later + exact date) | 3/3 | 3/3 | with-arm additionally gets a JEV closing verdict |

Findings: with a working search tool, this 4B reads short result sets carefully and both
arms score perfectly — verbatim quoting again ties retyping. The extension's additive
value on news search: the **JEV closing round now fires on comparison questions** (after a
taxonomy fix — "which is later/better/bigger" wording routed as chat 36.6% before, choice
91.7% after — and an extractor fix for 4-word options), producing e.g. *"JEV closing
decision: Tesserion-Halcyon acquisition 84.5% vs Kestrel DB 3.2 release 15.5%"*, and
`{news…}` provenance for every quoted fact. Two harness bugs found and fixed along the
way: the scorer rejected answers that merely *mentioned* decoys while explicitly ruling
them out (the correct behavior), and `[vars: …]` hint lines echoed by the model are now
stripped from final replies.

## Round-by-round (with-extension score / baseline score)

| round | config | with ext | without ext | verdict |
|---|---|---|---|---|
| 0 — original | thinking on, long hint, no guard/recovery | 14/18 | 16/18 | prompt overhead → ~4 length-flake failures |
| 1 — thinking off + bare `[vars: …]` hint | `enable_thinking:false`, names-only hint | 10/18 | 14/18 | **reverted**: 10× faster but the 4B got sloppy — wrong-file attributions, invented command outputs, wrong fields; placeholder compliance fell to 0/3 everywhere |
| 2 — kept from round 1 | thinking on, medium hint, verification guard, flake-recovery `continue` | **17/18** | 17/18 | flake failures eliminated; baseline shows its first genuine retype-drift failure (quote_hard); with-arm's one failure is a model debugging spiral (guard correctly silent — no false positive) |

## What was kept (all in `extension/index.ts`)

1. **Flake-recovery net** — `agent_before_settle` returns `{continue: true}` once when the
   run ended `stopReason:"length"` with no answer text; the with-arm's dominant failure
   mode (empty replies after thinking loops) is gone. Bounded to one retry per run.
2. **Medium discovery hint** — `[vars: a b] — quote these as {name} placeholders …`.
   The long sentence (round 0) was token-heavy; bare names (round 1) lost all compliance;
   the middle form restored it (smoke substitution check green again).
3. **Verification guard** — deterministic cross-check: final reply claims success
   (verified/now prints/…) while the last recorded `bash{N}_out` is an error → a ⚠ block
   with the recorded error tail is appended. Targets the measured "hallucinated
   verification" failure; verified no false positive on a mid-debugging run.
4. **`DH_SPARK_THINK=0`** — opt-in thinking-off for ~10× latency, documented with its
   measured accuracy trade-off on this model. (Also applies to the checker's nested calls.)

## Residual gap

17/17 tie: at this model scale verbatim quoting ties retyping when the string is near in
context; the extension's remaining value is the failure-mode insurance (no empty replies,
claim/error mismatch flagged, auditable {var} provenance, structured-request checker and
JEV closing rounds) rather than raw everyday-task accuracy.
